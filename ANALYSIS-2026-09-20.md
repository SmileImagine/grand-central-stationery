## 2. Findings

Each finding was checked in the browser, not inferred.

**F1. The binary search measured an element mid-transition.** Both visible layers carry `transition: font-size 0.22s`. Setting `style.fontSize` and reading `scrollHeight` in the same tick returns layout at the *old* size: measured `300 → 300 (immediately) → 724 (after 700 ms)`. So every probe in `binaryFit` returned the same answer regardless of `mid`. If the old size fit, the search converged to the guess; if it overflowed, it converged to `minFont` (4 vmin). The next keystroke started from that extreme and went the other way. That is the "wild fluctuation". The search itself was fine; the measurement was of the wrong thing.

**F2. The area formula ignores the box and the wrapping.** `k / sqrt(len + lines/2)` has no aspect ratio, no glyph metrics and no notion of which line wraps. Eight one-letter lines get 37.5 vmin, which stacks to 330 vmin tall. A single letter gets 100 vmin, whose 1.1 line box is already taller than the 96 vh content area. The user's note that it was "not optimized for incomplete lines" understates it: it cannot see lines at all.

**F3. ♯ and ♭ are not in the font.** Atkinson Hyperlegible Mono has no U+266F/U+266D; the browser substitutes a fallback glyph 60.2 px wide against a 63.2 px cell (at 100 px). Every accidental shifted the rest of its line by ~0.05 ch in the shadow but not in the textarea, so the caret drifted. v3 tried `margin-left: ±0.15em`; v3.1 wrapped the pair in a 2 ch `inline-flex` token, which fixes width but makes the token atomic, so the shadow gains line-break opportunities the textarea does not have.

**F4. Trailing newline mismatch.** A textarea whose value ends in `\n` shows an empty last line; a div does not (`"A\n"` → 2 rows vs 1). Empty text: 1 row vs 0. Appending a zero-width space to the div restores parity in every case tested.

**F5. v3.1 copies a pixel line-height onto its probe.** `getComputedStyle(...).lineHeight` for unitless `1.1` reads back as pixels (`"44px"` at 40 px). Applied to a 100 px probe, `lineHeightPerPx` came out around 0.44 instead of 1.1, so the height limit was several times too generous.

**F6. v3.1's fixed-point loop can 2-cycle.** Size → columns → rows → size passes through `floor` and `ceil`; at a wrap boundary the iterates alternate between two sizes and the loop returns whichever it stops on after four steps. This is the "line suddenly changes length" symptom in model form.

**F7. Binary Resize v1** is a linear scan (not binary), uses `clientWidth` including padding, measures the line height of an inline span under the body's `line-height: normal`, and counts rows as `ceil(len / cols)`, which ignores word boundaries and under-counts.

**F8. Latency.** A 50 ms debounce plus a rAF adds 60–70 ms to every keystroke. The fit is sub-millisecond, so no debounce is needed.

**F9. Scrollbar flash.** Visible layers use `overflow: auto`; while the size animates down after text grows, the intermediate sizes overflow and the textarea shows a scrollbar for up to 220 ms.

**F10. Colouring inside words.** Any capital A–G is coloured, so "Go" and "About" get a coloured first letter, and "About" rendered as "A♭out".

**F11. Wrap-rule parity is otherwise exact.** Div and textarea gave the same row count on 30 cases: exact fill, overflow by one, trailing spaces (hang), leading spaces, long words (break in place after moving to a fresh row), hyphens and en dashes (break after), `/` and `,` (no break), tabs (8-cell stops), NBSP, punctuation, and multi-paragraph text.

**F12. Fonts come from Google's CDN.** First paint uses fallback-font metrics, and the page needs internet in the classroom.

## 3. What v4 changes

The visual behaviour is unchanged: same font, same colours, same 0.22 s size transition on every keystroke, same shadow-layer structure. The sizing engine is replaced.

**Exact grid fitter (no feedback loop).** For a monospace grid with cell width `a` em and line pitch `L` em in a box `W × H`:

- `widthBound(c) = W / (a · c)` decreases as the column count `c` grows;
- `heightBound(c) = H / (L · rows(c) + overhang)` never decreases, because more columns never produce more rows (greedy first-fit is optimal);
- the answer is `max over c of min(widthBound, heightBound)`, and the two curves cross once, so a binary search on `c` finds it in about `log2(longest line)` evaluations.

`rows(c)` is a greedy word-wrap on the character grid that mirrors `pre-wrap` + `break-word` as verified in F11. Nothing here reads the DOM, so the result is a pure function of the text and the box. There is nothing to oscillate.

**Metrics measured once, not per keystroke.** Cell width, line pitch and a bottom overhang of 0.10 em are read from `offsetWidth`/`scrollHeight` on a 1 px inner probe at 1000 px. The overhang exists because the font's content box (1.3 em) pokes out below the last 1.1 em line box and counts as overflow. Layout properties are used deliberately: `getBoundingClientRect` reports transformed pixels and returned a halved cell width under the browser pane's scaled mobile emulation, which sent the fit 2× too large. A Range's bounding height was also wrong for line pitch (it spans glyph boxes and read 1.2 for a 1.1 line-height). Re-measured on `ResizeObserver` and `document.fonts.ready`.

**One-shot safety net.** A hidden, transition-free third layer gets the plain text at the computed size and is checked once for overflow; on failure it steps down 2 % (max 8 steps). In 18 test cases it never fired.

**Accidentals as overlays.** The typed `#`/`b` stays in the DOM (transparent) and the ♯/♭ glyph is painted over it by an absolutely positioned `::after` in a 1 ch box. Shadow and textarea are now byte-identical in text content, so they cannot wrap differently.

**Parity fixes.** Zero-width space appended to the shadow (F4); `font-weight: 700` on all layers (bold and regular advances are identical in this font, but now nothing depends on it); `font-kerning: none`.

**Latency.** `input` calls `update()` synchronously; rAF is used only to coalesce resize.

**Overflow.** Layers are `overflow: hidden` unless the size clamps at `MIN_PX` (8 px), when scrolling is enabled. This removes the scrollbar flash (F9).

**Whole words.** A pure maximizer will happily split a word when that buys size (on a phone-shaped box, "Open your books" became "Open / your / book / s"). `WHOLE_WORDS = true` restricts the column search to at least the longest unbreakable run, which is what v3.1's `tokenBound` was reaching for. Runs longer than `WHOLE_WORD_MAX` (15 cells) are exempt, because an unspaced melody such as a 63-letter "ABCDEFG…" run would otherwise be forced onto one line and drop from 104 px to 18 px. Set `WHOLE_WORDS` to `false` for the pure maximum.

**Accidental heuristic.** `#`/`b` after a note letter is an accidental unless a lowercase letter follows, so "Ab" is A-flat and "About" is A + "bout". Capitals inside words are still coloured (unchanged from v3); if you want only standalone note names coloured, that is a one-line regex change and I would rather you decide.

### Verification

18 texts (scale table, single letter, descender, empty, one long sentence, many one-letter lines, trailing newline, blank line, 34-letter word, hyphen chains, a 120-character paragraph, a 63-character run, multiple spaces, tabs, 40 lines):

| Check | Result |
|---|---|
| Shadow fits (no overflow) | 18 / 18 |
| Textarea fits | 18 / 18 |
| Safety net needed | 0 / 18 |
| Overflows at +2 % size (tight) | 12 / 18; the rest are within ~2 % |
| Time per update including render | 0.3–6.5 ms (40 lines) |
| Same checks under a 375×812 scaled mobile emulation | pass |

The loose cases are intentional: half a pixel of width slack flips a column at exact boundaries, and the fitter keeps the glyph box inside the padding rather than letting descenders bleed into it.

Known limits: `?` and `!` also create break-after opportunities in Chrome that the model does not know about (it over-counts rows, which is the safe direction); glyphs that are not 1 ch wide (emoji, CJK) fall to the safety net; IME composition is untested.

## 4. Solution space and migration cost/benefit

Constraints carried through: single HTML file, no install, largest possible text, per-keystroke size shift, intentional newlines respected, colour-coded note names.

| # | Approach | What changes | Effort | Risk | What you gain | Verdict |
|---|---|---|---|---|---|---|
| A | **Shadow layer + exact grid fitter (v4)** | sizing engine only | done | low | correctness, instant, no oscillation | **ship** |
| B | Shadow layer + hidden-twin binary search (DOM truth) | replace fitter with ~8 layouts on the transition-free twin | ½ day | low | drops the fixed-width requirement | good fallback; keep as safety net only |
| C | Canvas `measureText` fitter (proportional exact) | measure word widths (cached), same greedy wrap and same max-min search | 1 day | medium: canvas vs DOM sub-pixel differences | proportional Atkinson Hyperlegible at full accuracy, still algebraic | **next step if you want a proportional face**; pair with B's check |
| D | Single layer: `contenteditable="plaintext-only"` + CSS Custom Highlight API | remove textarea and shadow; colour ranges with `::highlight()` | 1–2 days | medium: paste/undo/IME quirks; Firefox ≥140, Safari ≥17.2 | caret correct by construction; unlocks `text-wrap: balance`/`pretty` | worth it only if caret drift returns; ♯/♭ overlays get harder (Highlight API cannot substitute glyphs) |
| E | Canvas/SVG renderer + hidden input | custom text layout and paint | 3–5 days | high: selection, caret, scrolling, accessibility, HiDPI | any font, per-letter animation, colour fades, fully offline | only if animation ambitions grow |
| F | Library fitters (fitty, textFit, FitText) | drop-in | hours | same transition pitfall; no wrap awareness | nothing over A/B | skip |
| G | Lookup table (the 3D LUT lab) | manual data collection | days | incomplete coverage | nothing over A | superseded |
| H | Framework or PWA migration | build tooling | days | none functional | nothing | skip; keep one file |

Small add-ons that fit any option: embed the woff2 as base64 for offline use (~100 KB per axis file), `height: 100dvh` for tablets, a `?text=` URL parameter for prepared slides, and `localStorage` to restore the last text. None are in v4.

### Recommendation

Stay on A. The one open design question is proportional versus monospace: distance legibility is better with the proportional Atkinson Hyperlegible, and C keeps the instant algebraic feel while lifting that constraint. D is the principled end-state for the "shadow text is a workaround" concern, but its cost is only justified if the overlay approach breaks in practice.

## 5. Proportional variant (option C, built 2026-09-20)

File: `Grand Central Stationery ChromaNotes Proportional v1.html`. Same shadow-layer structure, transition, colours and safety net as v4; the grid fitter is replaced and the text face is selectable.

**Fitter.** Token advances are measured once on a 2D canvas at 100 px with `fontKerning = 'none'` (the layers use `font-kerning: none`, so advances are additive) and cached per token. Row counting is the same greedy wrap as v4 but in pixels: spaces hang, hyphens and dashes break after, an over-wide word moves to a fresh row and then breaks per glyph, tabs advance to the next multiple of eight space widths. Because the height used never decreases as the size grows, a plain binary search on the font size (24 steps, 0.01 px) finds the maximum. `WHOLE_WORDS` caps the size so the widest run of at most 15 characters stays on one row.

**Canvas versus DOM.** For six sample strings across five faces, canvas advances and DOM layout widths at 100 px differed by at most 0.007 px. The model is effectively exact; the DOM safety net stayed idle in every test.

**Fonts.** A corner dropdown (also `?font=<key>`) switches between Atkinson Hyperlegible, Atkinson Hyperlegible Next, Atkinson Hyperlegible Mono, Lexend and Andika. Any Google Fonts family can be added to the `FONTS` table; only the chosen family downloads. The ♯/♭ overlays come from Noto Music, a real music font, instead of whatever fallback the browser finds. Two things bit here and are worth remembering:

- Noto Music's content box is 1.79 em tall, so an overlay with its natural height counted as overflow on any last line carrying an accidental. The overlay is now a zero-height box with `contain: layout`, which cannot contribute overflow.
- An absolutely positioned overlay inside an inline span is positioned from that span's content box, whose top is one font ascent above the baseline. The calibration that scales the symbol to cap height and puts its ink on the baseline uses canvas `fontBoundingBoxAscent` and `actualBoundingBox*` for both fonts and recomputes on every font switch.

**Verification.** 23 texts × 5 faces: shadow and textarea fit 115 / 115, safety net 0 / 115, within 2 % of tight in most cases (Andika is looser because its 0.26 em overhang is large relative to its line box).

**Whether to migrate.** The proportional build is the better classroom display: Atkinson Hyperlegible and Andika are more legible at distance than the mono face, and the fitter is no slower. The mono v4 remains simpler to reason about and has no canvas dependency. Both stay single files with no build step.

## 6. Follow-up changes (2026-09-20, later)

Both builds (mono v4 and Proportional v1) received the same two changes.

**Accidentals are now real characters.** The overlay is gone. When a `#` or `b` is typed after a note letter, the textarea's own text is rewritten to ♯ (U+266F) or ♭ (U+266D), and back to ASCII if a lowercase letter follows ("About"). Every swap is one UTF-16 unit for one, so the caret offset is unchanged (restored explicitly, because `setRangeText`'s preserve mode collapses a caret at the replaced range's end). Both layers share the font-family chain `<text face>, 'Noto Music', system-ui`, so the symbol comes from the same face in both, wraps identically (verified on three wrapping strings: equal textarea and div heights), adds no overflow (row height with and without ♯ is identical), and sits tight against the letter like printed notation. The shadow nudges ♯ up 0.18 em and ♭ 0.03 em with `position: relative`, which never affects layout. The canvas fitter measures with the same fallback list; the mono grid fitter counts the symbol as one cell, which is conservative because it is narrower. Side effect: copied text contains ♯/♭ characters.

**The flicker on rapid deletion.** Diagnosis: not overshoot (the old easing peaked 0.3 % over target and no frame overflowed) but ordinary re-wrapping. While `font-size` animated from 86 px to 119 px the row count walked 4 → 5 → 6, so words hopped between lines for the whole 220 ms, and each keystroke restarted that. Fix: both layers are laid out at the final size immediately and animate `transform: scale()` from the size the viewer currently sees (previous size × current animated scale, so rapid keystrokes stay continuous) to 1. Verified: during the animation the row count is constant (one value seen) while the scale runs 0.725 → 1. Cost: transforms are composited and skip layout, so this is cheaper than the font-size animation, not dearer. No look-ahead is needed.

## 7. Notation mode prototype (abcjs)

File: `Grand Central Stationery Notation v1.html`. A typing strip along the bottom takes ABC text; the score fills everything above it.

**Input.** Users type music only. If the text has no `K:` line, a header `X:1 / L:1/4 / K:C` is supplied, so `C D E F | G A B c |` alone renders. Each typed newline is a new staff line, matching the stationery's rule that intentional newlines are respected. Syntax problems appear as abcjs warnings beside the strip instead of breaking the render.

**Largest size that fits.** abcjs stretches each staff line to a requested staff width, and grows the drawing to its natural width when the request is too narrow. Because the line count is fixed by the typed newlines, the drawing's height does not depend on the staff width. So: render once to learn the height, set the staff width so the drawing's aspect matches the box, render again, and scale the SVG by `min(W/width, H/height)`. Two renders cost 2 to 6 ms for a few bars. abcjs's `responsive: 'resize'` option is deliberately not used: it rewrites the container's inline style into a padding-bottom aspect hack with an absolutely positioned SVG, which collapses the flex box.

**ChromaNotes colours and letters.** abcjs exposes the parsed tune next to the SVG, with a handle from each notehead to its `<path>`. The written letter plus any explicit accidental come from the parse; key-signature accidentals and accidentals earlier in the bar are applied in a small pass so the colour and the letter reflect the sounding pitch (verified: in `K:G`, `F ^C _B =F` spells F♯ C♯ B♭ F). Enharmonics share a colour in this palette, so pitch class is enough for colour; the spelling only matters for the letter. Heads, stems, flags and beams take the colour; ledger lines stay black. The letter is an SVG `<text>` centred on the head's bounding box, white on filled heads and coloured on hollow (half and whole) heads. Only the bare letter goes in the head, because the accidental is already engraved beside the note; the spelled name (F♯) is kept in the data for a caption or a tooltip later. abcjs also pins its container to a fixed inline height after every render, which must be cleared once the SVG is rescaled.

**Playback.** abcjs's built-in synthesiser is wired to a play button; the tune is reloaded into it on every render.

**Not done.** Automatic re-flow of bars per line (abcjs `wrap`) would give larger sizes for long tunes but ignores typed newlines, so it was left out. Cursor highlighting during playback, lyrics colouring and a larger control strip are straightforward follow-ups.

## 8. Zero-width accidentals (2026-09-20, later)

Request: "C♭" should take the same width as "C" in the text builds. Any CSS-only approach breaks the textarea/shadow parity, because the textarea cannot style single characters. So the width lives in the font instead: `GCS Accidentals` is a 654-byte woff2 embedded in both text builds, containing only ♯ and ♭ with an advance width of zero, drawn at about half size and raised to sit between 0.28 em and 0.66 em to the right of the letter's origin. Outlines are Noto Music's (OFL, renamed as required). Its `@font-face` carries `unicode-range: U+266D, U+266F` and it is first in the font chain, so it claims only those two characters in every face.

Consequences: the textarea, the shadow and the fitters all see the same zero advance (verified: "C", "C♭" and "C♯" measure identically in the DOM and on the canvas in all five faces); the mono grid fitter simply drops the two characters from its cell count; aligned columns such as `C  D  E  F` over `C♭ D♭ E♭ F♭` line up in the mono face; the accidental overlaps the following space, so `C♭D` with no space would touch. The font is also saved as `gcs-accidentals.woff2` beside the HTML files.

## 9. Notation mode, second pass (2026-09-20, later)

**Small accidentals that do not displace notes.** abcjs reserves layout space for every accidental and has no size option, so shrinking the glyph alone would leave the gap. The displayed staff is now laid out from a copy of the ABC with the accidentals stripped (music lines only; header, lyric and directive lines, quoted chord symbols, inline fields and decorations are left untouched), so the notes sit where they would without them. The original text is parsed off-screen for pitches, playback and timing, and the two parses are aligned by element order (notes, rests and bar lines); if stripping ever changes the element count the page falls back to displaying the original. Accidentals are then drawn as small Noto Music glyphs, 1.4 notehead heights tall (abcjs draws about 2.2), tucked against the left of the head in the note's colour. Verified: head-to-head gaps are even across notes with and without accidentals, and ♯ ♭ ♮ all render.

**Playback cursor.** The synthesiser plays the original parse. Its timing events carry the off-screen SVG groups; a map from those groups to element indices finds the displayed note, which gets a drop-shadow highlight and an orange cursor line at its left edge. Vertical extent comes from the event because the vertical layout is identical in both parses.

**Lyrics.** `w:` lines render in Atkinson Hyperlegible bold via abcjs's `vocalfont` format option (so abcjs measures the right widths) and each syllable takes its note's colour.

## 10. Notation third pass and the cell page (2026-09-20, later)

**Accidentals on the right line.** The small accidentals were low because the glyph's em box, not its ink, was being centred, and because the glyph metrics had been cached before Noto Music finished loading. Google Fonts serves Noto Music as unicode-range subsets, and `document.fonts.load(font)` with no text fetches only the Latin subset, so the canvas measured a fallback face. The load now names the accidental characters, metrics are cached only once `fonts.check` passes for them, and each glyph's optical centre (the whole ink for ♯ and ♮, the bowl for ♭) is placed exactly on the notehead's centre. Size is 1.8 head heights.

**Lyrics.** Regular weight. The music is laid out at a lyric size of 9 staff units, so abcjs widens the spacing only where a syllable exceeds that, and the lyric font then grows to the largest size at which no two neighbouring syllables touch and none runs past the staff edges (`--lyric-min`, `--lyric-max`). This is the stationery's own rule applied to syllables, whose "lines" are the gaps between note positions.

**Cells page.** `Grand Central Stationery Cells v1.html` combines both engines as classes that mount into any positioned container. A cell is `{type, text}`; text cells use the proportional engine (shadow layers, canvas fitter, transform animation, zero-width accidentals) and notation cells the abcjs engine (score box plus a source strip). Edit mode stacks cells at fixed heights with a header for type, order, delete and "present from here"; Cmd+Enter adds a text cell below the current one and Cmd+Shift+Enter a notation cell. Present mode shows one cell at full viewport, PageDown / PageUp move, Esc returns, and the cell's textarea keeps focus so typing stays live. Cells autosave to localStorage and export or import as a plain text file with `=== text` / `=== abc` separators. Two things bit: engines must be constructed after their element is in the document (abcjs finds its audio box by id), and hidden cells read zero or NaN sizes, so both engines skip work when their box is not laid out. Note also that Chrome pauses requestAnimationFrame in background tabs, which made a hidden test tab look broken; the first paint of a text cell is now synchronous.

## 11. Cells page: headings, dark mode, cursor (2026-09-20, later)

**Heading cells** are text cells with `centered: true`: `text-align: center` on all three layers, and the visible layers (not the measuring one) get extra top padding equal to half the unused height, computed from the fitted row count. Both visible layers get the same padding, so the caret stays aligned. Edit-mode height is `--heading-cell-h`.

**Dark mode** is a set of CSS variables (`--bg`, `--ink`, `--panel`, `--line`, …) with a `data-theme` override on the root and a `prefers-color-scheme` default. abcjs draws staff, clef, bar lines and rests with `currentColor`, so `.paper svg { color: var(--ink) }` recolours the engraving; ledger lines and staff paths are covered explicitly. ChromaNotes colours are unchanged in both themes. The toggle stores its choice; clearing it returns to following the system.

**Cursor.** A rounded bar with a glow lands on each note as it sounds, then glides to the next note over exactly the interval between the two timing events (`transition: transform <dt>ms linear`), so it arrives as the next note starts and is re-synced there; it jumps rather than glides across a line break. The sounding note pops (a 0.32 s scale keyframe about its own centre) and glows in its own colour; its lyric syllable goes bold; the bar fades at the end. Verified: a 334 ms glide for quarter notes at the default tempo.

**abcjs modifications, assessed.** Everything the stationery needs was achievable by post-processing the SVG and the parsed tune, so a fork is not recommended. Upstream requests worth filing: an option to scale accidentals and their reserved spacing; a responsive mode that does not rewrite the container's inline style; a lyric layout mode that never widens the music; and a documented notehead-position API (today reached through `abselem.heads[].graphelem`). Pin the CDN version (6.7.0 tested) or self-host the file for offline classrooms.

## 12. Offline build (2026-09-20, later)

All four pages now load only local files: `fonts/fonts.css` with 17 woff2 subsets (latin, latin-ext and the music range) of the six families, `vendor/abcjs-basic-min.js` and `vendor/abcjs-audio.css` pinned at 6.7.0, and `vendor/soundfont/acoustic_grand_piano-mp3/` with the 88 piano samples abcjs fetches at play time (6.7 MB). Verified: the cells page makes zero requests outside its own origin, and pressing Play fetches samples from the local folder. Browsers refuse to let a `file://` page fetch the samples, so `serve.command` starts a local server and opens the page; everything except playback also works when a page is opened straight from Finder. A `README.md` and `.gitignore` were added for the repository.

## 13. Notehead touch-up (2026-09-20, later)

Two rendering defects, both self-inflicted. abcjs fills every shape and sets `stroke="none"` on its groups, but the SVG root carries `stroke="currentColor"`. The decoration code set a stroke on noteheads and stems in the note colour, and the CSS gave staff and ledger lines a stroke as well, so every edge grew a one-unit outline: heads looked fuzzy and swallowed the ledger lines. The letters and accidentals appended to the root inherited the root's stroke and drew with a dark outline, which read as pixelation. Fix: fills only everywhere, and `stroke: none` on every element the page adds; the cursor line in Notation v1 is the one intentional stroke. The abcjs audio stylesheet assumes a dark grey box; with the box made transparent its light icons vanished on the light theme, so icons, progress bar and clock now use the theme's ink and accent colours.

## 14. Letter contrast in dark mode (2026-09-20, later)

In the light theme a white letter reads on every ChromaNotes head. In the dark theme a yellow head and a white letter both sit far above the background, so they merge. A per-head luminance rule was tried first; the user preferred one rule: letters are white in the light theme and black in the dark theme. Notation cells re-render on a theme change, including a system theme change.

## 15. 3D present mode (2026-09-20, later)

The editor the user remembered was Strut (impress.js-based, with a 3D overview). The cells page now has a "Present 3D" mode built on impress.js 2.0.0, vendored as `vendor/impress.js`.

**Structure.** On entry the cell elements are moved, engines and all, into the impress root as steps, preceded by an overview step whose scale is derived from the bounding box of every cell, so the camera starts pulled back showing all cells rendered live and then flies into each one. PageDown / PageUp / Esc work from inside a cell's text field because impress.js's form plugin stops key events at text fields; the same keys are handled at the field by the page. Clicking any non-active cell in the overview flies to it (impress.js's own click delegate). On exit impress is torn down and the cells return to the edit list; the engines re-fit through their resize observers.

**Layout.** Each cell may carry `pos` (`x`, `y`, `z`, `r`, `s`) and `bg`; blanks fall back to an automatic zigzag of four cells per row with a slight alternating rotation. The "3D" button in a cell header opens a row of inputs for these, and the export separator carries them as a JSON tail (`=== text {"x":1500,"bg":"#123456"}`), which the importer reads back. A cell's background colour becomes the stage background while it is active, with a 0.9 s transition, which is the Strut behaviour the user described.

**Gotchas.** impress.js's `tear()` rebuilds its root through `innerHTML`, which serialises and re-creates every step: textarea values vanish and the engines are left driving detached originals. The page therefore makes the overview the active step, moves the original cells back to the edit list, and only then tears down a root holding just the overview. impress.js also reads `document.body` while loading, so it must be loaded with `defer` (in the head without it, the script throws and the global `impress` resolves to the element with that id). The step size must equal the configured canvas size for a cell to fill the screen at scale 1, so the root's data-width/height are set from the viewport on entry.

## 16. Bugs from testing the 3D mode (2026-09-21)

**Cursor missing on the second line.** The bar's vertical extent came from the timing event, which describes the hidden render. The displayed render is re-laid out with the fitted lyric size, so its system spacing differs and the bar landed off the visible staff. The bar now takes its extent from the displayed staff of the event's line (`.abcjs-staff.abcjs-l<n>`). Same fix in Notation v1.

**Speaker console over the page.** impress.js bundles a speaker-console plugin (P) and a help plugin (H, ?) that register permanent key handlers on the window and document, outside its teardown. Its form plugin, which shields text fields, is torn down. So after one 3D session, typing a "p" in a cell in the classic present mode opened the console, which in this environment wrote its template over the page: the "Click to open speaker console" blocker and iframes of every step. Now every key typed in a cell stops at the field (our Cmd+Enter and navigation keys are handled there), and P, H and ? are swallowed in the window's capture phase everywhere else.

**Rotation and overlap.** impress.js does re-initialise on re-entry (teardown deletes the instance), and rotation reads `data-rotate-z`; the six degrees of freedom are `data-x`, `data-y`, `data-z`, `data-rotate-x` (pitch), `data-rotate-y` (yaw) and `data-rotate-z` (roll), with `data-scale` as a seventh. The layout row now exposes all six. Non-active cells are dimmed to 35 % opacity outside the overview, so overlapping cells read as background rather than clutter.

## 17. Playback from file:// (2026-09-21)

Opening the cells page straight from disk and pressing Play spun forever. abcjs loads each sample with an XMLHttpRequest and resolves only on HTTP 200; on a `file://` page Chrome refuses the request, and abcjs's promise never settles. Script tags do load from disk, so `vendor/soundfont/piano-embedded.js` (9.2 MB) carries the 88 samples as base64, and on `file://` pages only (or with `?embeddedsf` for testing) a small wrapper around XMLHttpRequest answers requests under `vendor/soundfont/` from that data, waiting for the script if it is still loading, and passes every other request through untouched. Served pages keep fetching the individual files.

## 18. Cursor sync (2026-09-21)

Measured during real playback: the synthesiser's timing events arrive on the tune's schedule to within a few milliseconds (wall-clock 334, 660, 999 ms against 333, 667, 1000 ms), so audio and events were never out of sync. The bar was: it left each note the instant it sounded and spent the whole duration travelling, so during a long note it hovered in the space after the note, which reads as running ahead. Now the bar lands on the note and rests there for the note's duration minus a short hop (30 % of the duration, at most 220 ms), then hops to the next note, arriving as it sounds. Rest and hop are one CSS transition with a delay, and every event re-syncs the bar to the synthesiser's clock. Measured: at 20 % and 60 % of each note the bar sits on that note; at 95 % it is nearly at the next one.

**Smoothed (later the same day).** The rest-then-hop version stopped dead and then started, which reads as a jerk. The bar is now one Web Animations keyframe sequence per note: a short settle from wherever the bar is onto the note, a slow drift across the notehead (about 12 units, or 30 % of the gap if smaller) for the body of the note, and an accelerating hop that arrives as the next note sounds. Each synthesiser event starts a fresh sequence from the bar's current position, so a small timing drift never snaps. Measured over 297 frames on a passage with a whole note: no backwards motion, per-frame movement under 15 units even inside the hops, and the bar on or within the notehead at 10 %, 40 % and 65 % of every note.

## 19. Proportional spacing, latency, and editing during playback (2026-09-21)

**Proportional spacing.** abcjs has no directive for it (abcm2ps's `%%notespacingfactor` is not implemented), so it is done after layout. On each staff line, every note, rest and bar line of the first voice is moved so that its horizontal position is linear in time, keeping the first note and the final bar line where abcjs placed them, with interior bar lines set a small gap before the note that follows. The moves are CSS translations through a `--dx` custom property on the abcjs groups, and the pop keyframes include the same translation so highlighting does not undo it. The letters and small accidentals now live inside the note groups, so they move with the notes. Beams, ties and slurs are single paths spanning two notes; each is translated by its left note's shift and scaled horizontally so its right end lands on its right note. Lyrics, sized for abcjs's spacing, are shrunk together until no two neighbouring syllables touch. Verified: note positions fit a straight line in time with a residual of 0.04 units; the beam, slur and tie were stretched; the toggle restores the standard layout. It is a toolbar checkbox, on by default, and the choice is remembered.

**Cursor in proportional mode.** Position is linear in time, so the bar is one constant-speed sweep from wherever it is to the next note, re-synced at every event. Measured error against the exact linear position: under 5 units, a constant offset equal to the intentional latency delay below.

**Audio latency.** The synthesiser's timer fires when a note is scheduled, not when the speakers emit it. The page reads the audio context's base and output latency (22 ms on this machine's built-in output; hundreds of milliseconds over Bluetooth) and delays the picture by that amount.

**Editing during playback.** A re-render during playback replaced the hidden render the synthesiser's timer refers to and called abcjs's setTune, which stops the transport. Renders requested while playing are now deferred and applied when the tune finishes or the transport is paused. abcjs names its end-of-tune callback `onFinished`; the earlier `onFinish` was never called, which also explains why the bar had not been fading.

**Cursor dead after the first play (later the same day).** Reported as "after adding words the cursor would not reactivate, though the synthesiser plays". The words were coincidental. abcjs's `setTune(tune, false)` does not clear the controller's `isLoaded` flag, so after one play every later Play took the fast path and reused the previous tune's timer and audio buffer: old music, and timing events referencing a render that no longer existed, so nothing mapped to the cursor. Editing before ever playing worked because the flag was still false. The page now destroys the controller's timer and buffer and clears the flag after every new tune. The lyric-shrink step was also made null-safe and all post-processing is guarded so a failure there can never keep a tune from reaching the synthesiser.
